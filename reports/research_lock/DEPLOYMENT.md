# Runtime-fix: общая блокировка колёс на малой скорости

Baseline: main `2f7851364c6afe9786fad040e0938454d8b0d210`. Проверены отдельно
стандартные параметры v4 и optional `adaptive_v5.yaml`; параметры не меняются.
Исправление включено в общее ядро и работает с обоими профилями.

## Ошибка и исправление

Когда оба датчика после блокировки сообщали нули, первая ступень могла
отвергаться rate-gate, но повторяющиеся нули затем проходили innovation-gate
при модельной скорости около 1 м/с. Фильтр принимал ложную остановку.

Теперь новая нулевая оценка не используется для wheel-коррекции, если обе
тележки дают свежие нули с допустимым skew, а |модельной скорости| >0.25 м/с.
Статус: `ZERO_LOCK_SUSPECT`, режим остаётся `MODEL_ONLY`. Свежий held-ноль второй
тележки допускается как подтверждение, поэтому защита работает и при
чередующихся callbacks. Held-данные повторно не усваиваются. При замедлении
модели ниже существующего порога стандартное подтверждение остановки сохраняется.

## Результат на дополнительном сценарии

| Профиль | Event group-macro RMSE до, м/с | После | Снижение |
|---|---:|---:|---:|
| default v4 | 2.691426 | 0.409301 | 84.79% |
| adaptive v5 | 2.688770 | 0.316586 | 88.23% |

Для обоих: false-stop samples **200 → 0**; receiver-cases без подтверждённого
восстановления за 10 с **1 → 0**. Это counts отсчётов/сравнений, не 200 отдельных
событий. Event RMSE улучшился в 56 из 60 bag/fault/receiver-сравнений, в четырёх
не изменился; ухудшений нет. Данные обоих GNSS-приёмников сохранены.

Область проверки: **отдельная новая low-speed suite**. Для каждой из 19
validation-записей взята первая подходящая точка со средней wheel-скоростью
1..2 м/с, разницей тележек <0.15 м/с, командой >=0, после max(25 с, 10% записи)
и за 25 с до конца. Anchor выбирается по vehicle-данным без GNSS и без поиска
выгодного момента. Перед инъекцией 20 с разогрева, после — 10 с восстановления.
Блокировка длится 3 или 5 с: 38 сценариев, 60 сравнений с доступным GNSS.
Четыре bag без reference не становятся нулевой ошибкой.

**Это не 88% улучшения на всём датасете или старой suite.** На 19 чистых
validation-bag и 76 исходных fault-сценариях все сохранённые bag/receiver-метрики
скорости, scalar distance, coverage, false stops и recovery для каждого профиля
точно совпали со своим baseline. Скрипт `verify.py` проверяет это отдельно.

## История и ограничения

1. Затухание disturbance 2/5 с при общей потере данных отклонено:
   [результаты](../research_decay/REPORT.md).
2. Первая защита синхронных нулей не дала выигрыша на прежних >2 м/с anchors:
   [первый отчёт](REPORT.md). Noise×2 также не достиг порога.
3. Синтетический low-speed failure установлен до новой suite. План дополнительных
   anchors закреплён `96e37c4`, evaluator до измерений — `6190e82`.
4. Найден и исправлен отдельный async-callback failure; итоговый runtime и оба
   профиля повторно проверены. В Git сохранены промежуточные варианты и результаты.

Повторно используется validation, поэтому это проверка известного механизма
отказа и отбор решения, не независимый final test. Старые test-payloads не
читались повторно. Истинная внезапная остановка и блокировка колёс могут быть
неразличимы без независимого датчика: при ошибке модели защитное решение может
задержать признание настоящей остановки. На имеющемся clean validation такой
регрессии нет; не доказана универсальная безопасность или точность xyz.

## Проверки и воспроизведение

73 dependency-free runtime-теста, включая чередующиеся callbacks, блокировку
на малой скорости, настоящее торможение до остановки и отказ одной тележки.
29 исследовательских проверок. Runtime побайтно равен измеренному прототипу;
исходный baseline-core сверен с SHA256 опубликованной v4.

ROS CI включает отдельный тест установленной ноды с обоими профилями:
низкая скорость → нулевые чередующиеся тележки → восстановление → реальное
торможение до остановки. Он также выполняется offline при 2 CPU / 500 MB.
Это smoke; нового длительного latency benchmark нет.

```bash
python tools/research_lock/runner.py --output /tmp/wheel-lock-original-suite
python tools/research_lock/low_speed.py --output /tmp/wheel-lock-low-speed-suite
python tools/research_lock/verify.py \
  --original /tmp/wheel-lock-original-suite/results.json \
  --extension /tmp/wheel-lock-low-speed-suite/results.json
PYTHONPATH=src/reserve_odometry python3 -m unittest discover -s tests -v
python -m unittest discover -s research/tests -v
```

Для evaluator нужны закреплённые requirements-research и dataset. Runtime не
получает новых зависимостей или топиков. Созданный output нельзя перезаписывать.

Опубликованный ZIP v4 остаётся неизменным. Его frozen-source integrity проверяется
по содержимому самого ZIP, а не приравниванием нового рабочего кода к старому
release. `tools/finalization/package.py` намеренно не сможет выдать изменённый
runtime за старый freeze; для новой сдачи требуется отдельная финализация.
