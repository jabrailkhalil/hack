## Файлы и координаты

Обе карты пользователя прочитаны целиком, индексы путей проверены. Первая имеет
4710 точек и длину4708.927310м, обратная4709 точек/4708.561650м. Это два отдельных
направленных пути, не готовый замкнутый маршрут. Исходные поля x/y/z/tang/curv и
point_indices сохранены. Нет CRS, origin или сведения о связи концов.

Чисто геометрическая проверка по reference (НЕ вход модели) выявила: старт bag
лежит в509.635м от первой карты, конец в164.029м; для обратной514.319/160.944м.
Примерно77% reference poses близки к первой карте. Этот oracle показывает покрытие
данных, а не точность estimator. Карта не достраивалась по /localization.

Для GNSS проверена гипотеза WGS84 UTM37N с вычитанием (300000,6100000)м.
Гипотеза выбрана при исследовании масштаба координат/GNSS, не предоставлена
метаданными и не удостоверена организаторами. Translation/yaw/scale не обучались
на reference. Код требует явного allow_hypothesis или подтверждённого контракта.
Z выдаётся из исходной карты; высотный datum GNSS не объявляется установленным.

## Причинная позиция

Используются только готовый v8 s, внешние карты и rover NavSatFix. Курс из прошлых
GNSS fixes; frame/status/time проверяются. Проекция учитывает поворот плеча
(2.563,0,3) по касательной/уклону. На поворотах это приближение ориентации кузова,
не отдельная модель двух тележек. Все решения по выбору пути — без эталона.

До допустимой on-map привязки XYZ отсутствует. После конца пути XYZ отсутствует:
нет snap на500м, выдуманного кольца, clamp или копирования reference. После
инициализации путь не переключается. Raw s/v не меняются. Sparse update корректирует
только offset (gain.25, максимум1м, interval>=30s, innovation<=40м), на этом bag
фактически приняты6 поздних коррекций, каждая менее0.5м. Параметры не подбирались.

## Верификация

246 фактически выполненных тестов:34 pathgraph,27 frozen candidate,29 checker,
156 historical runtime. Не выдаём их за161 актуальных packaging/ROS tests.
Pure UTM implementation сверена с PROJ на16 точках региона (<2мм); это не
сертификация CRS данных. CSV сохраняет все9419 исходных XYZ точек точно;
legacy route interpolation разность не более1.46e-11м.

Полный повтор завершён: RESULT.json и7NPZ/39массивов совпали точно. Первоначальный
диагностический результат тоже совпал с финальным после исправления независимости
часов получения/источника. Ни параметры, ни маски, ни карту по метрике не меняли.
Подготовлен research/ros_node.py, наследующий текущую GuardedOdometryNode; он
не запускался в ROS. Статический тест запрещает reference topic и изменение v/s.
Чистый локальный projection-kernel benchmark не является ROS end-to-end latency.

Исходники: исторический численно эквивалентный snapshot плюс exact PR62 overlays,
19 baseline и10 candidate hashes проверены. Это не полный свежий ROS checkout.
Отдельная19-bag validation и ROS/DDS/Docker не выполнены. Основное решение main,
старые freezes и reports не перезаписаны. Raw DB не включён в Git/новый архив.

**Решение:** публиковать как opt-in исследовательскую ветку, не менять main.
Чтобы сделать полное решение, необходимы отсутствующие участки у конечных,
подтверждение преобразования GNSS→map и реально выполненная ROS-проверка.
