# Строгий выбор одного основного решения

## Вердикт

**Основное решение: v8, численный исходник e3b0c9c039d2953fbfcda51231263d38ef9f1024.** Ни один из пяти новых оценивателей godknows1337 не прошёл заранее записанные условия замены. Это выбор лучшего допустимого варианта на зафиксированном наборе, не доказательство универсального оптимума. Математическое ядро, ROS-адаптеры, Timeline, конфигурация v8 и основной launch не изменяются; сужается только устанавливаемая поверхность пакета.

Теперь устанавливаются ровно один executable `guarded_odometry_node`, один `odometry.launch.py` и один `champion_v8.yaml`. Старый unguarded entrypoint и альтернативные launch/config больше не устанавливаются. Исторические source fixtures/ветки/архив v4 сохранены, но не являются вариантами стандартного запуска. `build.sh`/`run.sh` используют отдельный `install_main`, чтобы не запускать оставшийся в старом install/ executable.

## Одинаковые данные и условия

19 существующих validation-bag, 15 с доступным GNSS, 9 reference-групп, 30 bag/receiver-пар, 698891 matched clean samples. Оба приёмника сохранены, четыре записи без эталона не считаются нулевой ошибкой. Никакого обучения, выбора параметров или доступа к final-test measurements для выбора победителя.

Одна причинная source-time сетка 20 Гц и одинаковые доступные held/new samples. У товарища используется его опубликованный OurObserver-порт, восстанавливающий исходные raw units; коэффициент 1/3.6 применяется ровно один раз. Возраст/повторные/недоступные сообщения не скрываются. Число matched samples одинаково у всех девяти методов; ранние публикации peer до инициализации v8 отдельно учтены. Все peer-исключения отсутствуют, обнаруженных future-sample нарушений нет.

**Это сравнение оценивателей на общем временном контракте, не двух native ROS-адаптеров.** H2 предназначен в том числе для поздних сообщений; его возможный выигрыш на другом arrival-clock/jitter-наборе этим опытом не исключается. Полные transport-latency/RSS peer-измерения не выполнялись. Две GNSS-антенны не являются независимыми поездками. Повторно использованный validation не является независимым test и не даёт официального балла.

## Основные результаты

Group-macro — среднее RMSE сначала внутри групп, затем между группами. Original fault RMSE считает только event-окна четырёх исходных отказов, не разбавляет их длинными штатными участками. Дистанция — скалярный reanchored span surrogate, **не ENU/XYZ и не terminal drift всего пути**.

## Отказы и локальные проигрыши не скрыты

76 исходных сценариев (bias передней тележки 5 с, выпадение обеих wheel speeds 5/10 с, common zero 3 с), плюс 38 резких common-mode и 38 slow-ramp сценариев: всего 152. **Команда управления доступна во время wheel dropout; это не отказ вообще всех входов.**

В исходных fault-окнах/восстановлении новые ложные STOPPED-отсчёты относительно GNSS>1 м/с: v8 0, A 136, B 20, C 20, H1 18, H2 32. Это receiver-wise отсчёты, не столько независимых эпизодов. Статусы методов различаются; у простого mean нет семантического STOPPED, поэтому отсутствие такого статуса не означает отсутствие ошибочной нулевой скорости. В raw evidence сохранена и отдельная false-zero метрика.

v8 не выигрывает на каждой записи: B лучше в 14 из 30 clean-пар, C в 13, H2 в 14, A в 10, H1 в 14. Например, B на 30618_437e855c/master даёт 0.031409 против 0.032730 м/с у v8. Но это не компенсирует агрегатные и safety-регрессии, пороги выбора после результата не менялись.

**Плавный одинаковый дрейф остаётся слабым местом v8.** Event RMSE v8 3.071476 м/с; B 3.099872, C 3.099070, H2 3.094651, mean 3.060703. После окончания drift среднее recovery v8 4.4075 с, A 1.1350, B 1.7341, C 1.7408, H1 1.9475, H2 1.6841, mean 0.3616 с. Защитные механизмы v8 мешают быстро вернуться после такого изменения. Ни одна модель не объявлена универсальным детектором общей пробуксовки.

## Почему выбран v8

Ни одна замена не выполнила предзарегистрированные ограничения: clean/fault/pooled regression <=0.5%, distance <=1%, per-bag clean <=max(0.005 м/с,5%), без новых false stops/non-recovery/coverage loss; дополнительно нужен >=2% clean либо >=5% original-fault gain. У всех пяти есть original-fault regression и нет необходимого primary gain. Более быстрое slow-drift recovery — реальное преимущество peer, но недостаточное основание ухудшать основные показатели в несколько раз.

Новые исследования R2/R3 рассмотрены по сохранённым вердиктам. Большинство REJECTED/INCONCLUSIVE; H16 с fault gain имеет distance regression выше допуска, H22 на момент снимка IN_PROGRESS. Начатые параллельно новые R4 не считаются готовыми победителями без завершённого сопоставимого отчёта. Нельзя сливать все механизмы вместе и присваивать смеси результаты отдельных экспериментов.

## Воспроизводимость и фактические проверки

Первый полный локальный прогон: Python 3.13.5, NumPy 2.3.5, четыре процесса, 525.53 с вычислительного времени. Это время offline replay, не ROS latency. v8 воспроизвёл опубликованную clean RMSE **точно**, max difference 0.0. Исходники frozen bench.py и hashes дополнительно сверены с ZIP, реально сохранённым GitHub Actions: совпадают побайтово.

После сужения упаковки локально пройдены **161 test invocation**, **43 research-integrity tests**, compile/build wheel. Wheel содержит ровно один executable, одну launch-конфигурацию и один YAML. Все 10 закреплённых файлов runtime/config/launch совпадают побайтово с исходным v8; коэффициенты и уравнения не менялись. Исторический v4 ZIP и его final-test evidence не переписаны.

**Свежая GitHub/ROS-проверка этой упаковки пока не завершена.** Первый удалённый preflight обнаружил неоднозначный исторический путь к fault windows; выбор ограничен каталогом H13 без изменения frozen hash. После исправления run 36230840124 и его повтор завершились до запуска steps, логи выполнения отсутствуют. Это не PASS, причина runner-отказа не установлена. Предыдущие ROS-проверки неизменного v8 не выдаются за новые проверки упаковки. Workflow и installed-surface/selected-fault tests сохранены для повторного запуска.

Полный raw archive `adjudication-local-results.zip` приложен к беседе: 452934 bytes, SHA256 `2b349de25a0e6b5e874fb78909fa57791e2155f03cba0f9eda16364ac5041143`. Он содержит все 19 per-bag JSON, 152 сценария, обе антенны, runtime diagnostics, prediction hashes, таблицу и access journal. Это локальный архив, не существующий GitHub Actions artifact. В репозитории сохранены воспроизводимый frozen runner, условия выбора, основные таблицы и решение; полный код peer берётся из его закреплённой ветки, не переобучается.
