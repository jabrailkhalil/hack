# Отбор v6: пять отклонённых гипотез, активный default v5

## Решение

**Оставлен профиль `v5_adaptive_05s` из PR #10 и сделан стандартным default.** В прежнем main `2f78513` он был только опциональным: стандартный запуск ещё использовал v4. Пять новых вариантов v6 не прошли заданные критерии, их патчи остаются только материалами экспериментов. Ядро, ROS-адаптер, временная логика и физические коэффициенты не заменены экспериментальными версиями.

Это выбор по точности скорости и устойчивости с ограничением регрессий, не универсально лучший алгоритм по каждой метрике. У v5 скалярная ошибка дистанции на 0.23% больше прежнего default. Runtime по-прежнему использует только три vehicle-топика, output 20 Гц без искусственного ожидания 60 мс.

19 validation-bag / 10 групп; GNSS-метрики доступны в 9 группах и 30 bag/receiver-парах. Четыре записи без reference не считаются нулевой ошибкой. В каждом раунде те же 76 fault-сценариев и 120 сравнений с reference. Оба GNSS-приёмника сохранены, timestamps и reference-маски одинаковы для всех кандидатов.

Оба baseline воспроизводят опубликованные показатели PR #10: проверено 468 числовых полей, максимальное абсолютное расхождение 0.0. Это повторное воспроизведение, не независимое доказательство обобщения. Distance — переякоренная скалярная ошибка на непрерывных GNSS-speed отрезках, не xyz и не полный terminal drift.

## Гипотезы и причины отказа

Планы закреплены до запуска каждого раунда: [round1](../../research/plan_v6.json), [round2](../../research/plan_v6_round2.json). Раунд 2 использовал выводы первого; это адаптивный поиск на повторно используемом validation. Final-test измерения не открывались и не пересчитывались.

Идея round1: принятая колёсная скорость относится к более раннему stamp, чем момент коррекции. Проверили перенос к текущему времени с 0.5 или 1.0 долей ограниченного модельного ускорения; исходные samples для gate/адаптации не менялись. Идея round2: ограниченно ослаблять устаревшую disturbance-поправку после потери доверенной пары, вместо бесконечного удержания. Проверена постоянная времени 2 с отдельно и с обоими вариантами переноса.

| Кандидат | Clean RMSE | Fault RMSE | Clean выигрыш к v5 | Fault изменение к v5 | Решение |
|---|---:|---:|---:|---:|---|
| Перенос 0.5 | 0.114707 | 0.542243 | +2.08% | хуже на 0.71% | отклонён |
| Перенос 1.0 | 0.114321 | 0.548618 | +2.40% | хуже на 1.89% | отклонён |
| Затухание 2 с | 0.117130 | 0.549825 | +0.007% | хуже на 2.12% | отклонён |
| Перенос 0.5 + затухание | 0.114688 | 0.553244 | +2.09% | хуже на 2.75% | отклонён |
| Перенос 1.0 + затухание | 0.114294 | 0.559361 | +2.43% | хуже на 3.89% | отклонён |

Критерий: минимум 2% clean gain **или** 5% fault gain относительно v5; не более 0.5% регрессии каждой основной агрегированной метрики и 1% дистанционной метрики; per-bag clean-регрессия не больше max(0.005 м/с, 5%); отсутствие потери coverage, дополнительных ложных остановок/невосстановлений и ошибок причинности. Порог **не смягчался** после просмотра результатов. Поиск закончен после заранее ограниченных последних трёх гипотез.

У всех пяти кандидатов fault-регрессия превышает разрешённые 0.5%, хотя некоторые лучше на обычных участках. Поэтому чистый RMSE не использован как единственный критерий. При отсутствии нового подходящего кандидата применён записанный до запуска fallback: подтверждённый v5, который проходит прежний минимум 5% fault gain относительно v4 при допустимых остальных регрессиях.

## Что изменилось в main

`config/default.yaml` теперь **побайтно равен `config/adaptive_v5.yaml`**. Единственный изменённый model-параметр против v4 — `adaptation_tau_s`: 8.0→0.5. Нода, core, route и timeline побайтно совпадают с опубликованным v4; rejected projection/decay fields не появились в активном Config.

`config/frozen_v4.yaml` сохраняет точный прежний default. Архив `submission/dist/reserve-odometry-v4.zip`, его SHA256, исходный FREEZE и final-test не переписаны. Старые source-хеши проверяются по неизменному архиву; активные хеши и config — отдельно по [PROMOTION.json](PROMOTION.json). Старый evaluator намеренно отклоняет активный default как не соответствующий исходному freeze.

Нельзя переносить final-test цифры v4 или её полный 24-минутный benchmark на v5. Новые проверки runtime и их длительности приведены в следующем разделе. Нового независимого test в этом цикле не было. Исходный v5 fault-gain bootstrap из прошлого отчёта включал ноль; повторный отбор на тех же группах не устраняет эту неопределённость.

[CI исходников e683e1f](https://github.com/jabrailkhalil/hack/actions/runs/36166820911): все четыре jobs success. Пройдены 70 dependency-free unit tests, 30 research-integrity checks, настоящий установленный ROS default launch, отдельный v5 launch, adapter и fault/pause/seek проверки. Те же ROS-проверки выполнены без сети в контейнере 2 CPU / 500000000 байт. Старый final-test не запускался заново.

Патчи `research/patches/v6-*.patch` применялись только в экспериментальной рабочей копии. Не применять их к рабочей ноде как «новую лучшую версию». Ручные исследовательские workflow создают новую папку результата для каждого run/attempt и не перезаписывают опубликованные раунды. Для точного исторического повтора доступны закреплённые commit/run каждого раунда.

Запуск активного профиля после сборки и source:

```bash
ros2 launch reserve_odometry odometry.launch.py
```

Для возврата к v4:

```bash
ros2 launch reserve_odometry odometry.launch.py \
  params_file:="$PWD/src/reserve_odometry/config/frozen_v4.yaml"
```

Базовые ограничения прежние: относительная (s,0,0), не ENU; единицы 1/3.6 требуют ответа организатора; произвольная common-mode ошибка двух колёс неоднозначна; тесты не являются сертификацией безопасности. Приватность репозитория и отправка на платформу не менялись.
