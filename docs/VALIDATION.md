## Разделение данных

Все восемь просмотренных bag помечены development. Разделить остальные по целым прогонам и двум vehicle-группам до оптимизации. При обнаружении общего исходного заезда объединить его фрагменты в одну группу. Сохранить manifest с seed, bag IDs, checksum, ролью каждого файла и версией параметров. Нельзя случайно перемешать соседние точки одного заезда между train и test.

Train: настройка масштаба (после разрешения), effective physics, задержек и порогов. Validation: выбор решения. Test: один финальный отчёт после заморозки. Отдельный стресс-тест: обучаться на 30618 и проверять на 30639. Не выбирать лучший приёмник задним числом по ошибке своего алгоритма.

## Сопоставление со скоростью GNSS

Сохранять bag-record order для inference. Выходы сопоставлять по source stamps. Реализован nearest match до 0.05 с, без интерполяции будущих inputs внутри observer. Постобработка reference допустима только в evaluator. Норма hypot(x,y) является рабочим определением горизонтальной скорости, а не подтверждённой формулой судьи; направление, вертикальную компоненту и frame следует уточнить.

Метрики: RMSE, MAE, signed bias, p95 абсолютной ошибки, coverage, количество несопоставленных точек. Отдельные срезы: движение/остановка, разгон/торможение, обе vehicle-группы, короткие и длинные записи. Разница между master и rover - индикатор качества эталона; она не разрешает скрывать неудобные измерения. Маски GNSS качества задавать независимо от ошибок модели.

## Положение: не подменять метрики

В текущем отчёте `integrated_speed_error_m_NOT_3D_POSITION` - интеграл разницы скорости только по непрерывным сопоставленным отрезкам. Это **не** end-point xyz error, не точный along-track drift всего bag и не подтверждение критерия положения. Условная дистанция интегрируется отдельно от GNSS fix; реальная 3D-оценка пока не проведена.

После согласования карты/origin считать `e_xyz = estimated_xyz - reference_xyz`, RMSE по компонентам и норме, terminal drift относительно полной длины, along/cross-track на известной разрешённой трассе. Учитывать высоту, качество fix, начальную систему и смещение антенны. Не выравнивать оценку на всём test-маршруте по его будущему GNSS: только разрешённая начальная привязка.

## Аномалии и причинность

Инъекции: front/rear скачок +5 м/с, один канал на нуле при движении, оба канала одинаково завышены, длительный юз, NaN/Inf, stale, дубликаты, перестановка, controller stuck, wheel scale ±1-3%, input gaps 0.1-10 с. Инъекции делать после формирования независимого reference и применять одну маску ко всем сравниваемым алгоритмам.

Проверять не только finite outputs, но и ошибку внутри аномалии, время восстановления, ложные остановки, ложные slip-срабатывания и рост uncertainty. Общая правдоподобная ошибка двух датчиков без независимой информации не всегда обнаружима. Об этом нужно говорить на защите.

Для anti-leakage выполнить тот же inference с удалёнными/перемешанными GNSS и с изменёнными всеми future-данными: уже выданные прогнозы не должны измениться. У каждого accepted sample timestamp <= output timestamp; каждый wheel sample обновляет состояние не больше одного раза.

## Быстродействие и воспроизводимость

`inference_input_callback_us` в JSON относится к вычислительному replay на машине разработки. Это не latency ROS/DDS, не hard real-time и не доказательство лимита памяти. Целевая проверка: 2 CPU, 512 MiB, сеть отключена, весь длинный bag, отсутствие роста RSS и сбросов на чистых данных. Пять секунд ROS smoke - лишь проверка интеграции.

Финальные отчёты должны содержать commit SHA, checksum данных, manifest split, конфигурацию, CPU/память, Python/ROS версии, команды, времена измерений и полную таблицу bag-level метрик. Никакого выбора только красивых графиков.
