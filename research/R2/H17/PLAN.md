Baseline: `65bba39ed05c781f3f69a65c02f69931152cbfd9`, настоящий `GuardedReadoutObserver`, профиль `src/reserve_odometry/config/guarded_readout_v7.yaml` (config из парного JSON проверяется по YAML), output Estimate/last_estimate; 20 Hz, alignment_delay_s=0, readout gain=1/holdoff=.5, inner wheel_time_compensation=0, adaptation_tau_s=.5. Ветка `research/round2-H17`. Движущийся main и H11/v8 не включать.

## Механизм и бюджет
Ровно три ненулевых L: .05, .10, .20 s. Ноль — canonical baseline и отдельная off-ablation, не вариант. Никакой непрерывной оптимизации, изменения tau=.3927619145850434, физики, wheel scale, gate, stop/zero-lock/recovery/readout или Timeline. H07/#22 менял tau тяги/торможения и получил fault-регрессию; здесь единственное изменение — аргумент drive_target: последняя уже наблюдённая команда со stamp <= t-L. В отличие от v6/PR14 это не перенос wheel measurement. H11/#26 — соседний quarantine, не часть H17.

Новый subclass GuardedReadoutObserver хранит только controller samples, реально переданные step неизменной Timeline. Между output ticks Timeline может отбросить промежуточные команды; скрытого доступа к её очередям нет. Это ограничение интерпретации физического delay, а не повод изменить Timeline. История <= .25 s плюс один predecessor, <=64 samples. Дубликаты/неупорядоченные stamps не добавляются; future/nonfinite/range/stale не принимаются. До наличия predecessor для t-L target использует neutral=0, без фальсификации source stamp. При невалидной текущей команде target neutral сразу; история не продлевает command_timeout=.5 s. Выбранная историческая команда также не может быть старше timeout относительно t. Guards/stop/readout и command_stale используют ИСХОДНУЮ текущую команду, не переписанный stamp. Off передаёт выполнение непосредственно baseline. В алгоритме нет reference, file/bag ID, fault oracle, NumPy/SciPy.

## Данные и порядок
1. Получить source-only snapshot и прочитать runtime/evaluator/tests/data roles. Snapshot не читает measurements. Автоматический стандартный CI на неизменённом baseline не является экспериментом кандидата.
2. Sanity: compile, исходные релевантные unit/integrity, exact off output/status/state compatibility; duplicates/stale/future/out-of-order, reset, finite/bounded history, causal prefix, zero-lock/stop/reacquire. Отдельно проверить реальный canonical baseline тем же score driver против независимой canonical factory и off на train/development, включая counters. Новые source manifests не переписывают исторические pins.
3. Train: все 64 штатных train bag, только три vehicle topic через штатный Store; GNSS не читается. Без fitting; coverage/transition и finite-output диагностика. Wheel label — только pseudo-reference. Train может не использоваться для выбора численных параметров.
4. Development: все 17 bag настоящей роли development, включая missing reference, оба receivers. Новый изолированный read-only loader проверяет роль ДО SQLite IO и bag/split hashes; никакого переименования ролей. Все 3 L сравниваются с заново исполняемым canonical v7, один score/matching/сетка/fault placement/aggregation. Исторические validation results НЕ используются для выбора.
5. Перед validation: для каждого варианта >=100 output ticks с effective delayed u != current u, >=20 qualifying command transitions из >=3 исходных development групп. На development >=3 группы с reference. Неактивный механизм/недостаточный coverage => INCONCLUSIVE (семейство не отвергать). Safety gate: отсутствие новых false stops/unrecovered по каждой доступной паре, coverage loss, causality/resets, NaN; source/disabled compatibility обязательны. Эти safety условия распространяются и на заранее заданные дополнительные suites.
6. Выбор: среди вариантов с достаточным покрытием и прошедших safety и общие regression guards (ниже) выбрать минимум clean group-macro RMSE, затем fault RMSE, затем меньшее L. Development minimum gain не обязателен для однократной validation, но все regression guards обязательны. Если ни один не проходит — REJECTED проверенной сетки, validation НЕ открывать. Если данных недостаточно — INCONCLUSIVE. Дополнительно показать лучшую L (включая 0) отдельно по development группам. При разных уникальных optima (численный tie 1e-10 m/s) физически общий L НЕ считать подтверждённым, даже при хорошем агрегате.
7. При наличии допустимого варианта — отдельный commit FREEZE (source SHA, SHA256 runtime/driver/evaluator/profile/split/plan и development evidence) ДО открытия validation. Один paired validation всех 19 bag, original suite; никаких изменений параметров после просмотра. При отсутствии допустимого варианта freeze/validation не имитировать.
8. Final/test measurements и исторические final-test results НЕ открывать и НЕ пересчитывать. Validation повторно использовался ранее, это не independent test.

## Один неизменный измеритель
Использовать исходные `tools/finalization/evaluate.py` score/replay/distance и `tools/research_v3/experiment.py` match/metrics, original fault placement `tools/research_guarded/compare.py: fault_windows`, group aggregation `tools/research_v6/compare.py: summary/macro`. Изолированный factory подставляет только Observer; alias baseline_v2 внутри score означает v7 только в этом driver и немедленно переименовывается в R2_v7. Дополнительный canonical control replay проверяет baseline тем же driver. Исторические models()/pins/decide, рассчитанные на v5, не выдаются за R2 и не редактируются. Новый R2 admission checker точно реализует контракт.

## Контракт (не менять после цифр)
Clean group-macro gain >=2% ИЛИ original fault-event group-macro gain >=5%. Clean/fault/pooled regression <=.5%, scalar-span distance <=1%. Clean каждого bag/receiver <= baseline+max(.005 m/s,5% baseline). Без потери n/coverage, дополнительных false stops, новых индивидуальных unrecovered, causality violations/unexpected resets. При baseline=0 допускается только candidate<=1e-12 для агрегата; reporting absolute delta, не division by zero. Missing evidence не считается zero. Показывать MAE, signed bias, p95, recovery, group/per-bag/per-receiver/per-fault и локальные регрессии. GNSS receivers не независимые поездки. Bootstrap не нужен для admission; не считать ticks независимыми.

## Заранее заданные diagnostics (НЕ замена original suite)
Command transitions на штатной causal .1 s vehicle grid: смена sign-mode (-1 ниже -.04, 0 deadband, +1 выше .04), валидные соседние ticks и wheels mean>.5 m/s. Для каждой группы показать число/тип переходов, first 2 s phase RMSE/MAE/bias, delayed/current target, drive_a и disturbance.
Дополнительная suite: первый переход в каждый новый режим при t>25 s, t<end-16 s, wheels>1 m/s; loss начинается transition+.05 s. Для каждого такого anchor отдельно both-wheel dropout 5 s и controller-only dropout 1 s; входы удаляет ВНЕШНИЙ driver, никогда algorithm. Ещё first low-speed (1<v<2 m/s) anchor по той же vehicle grid с t>max(25,.1*end), t<end-25: common zero-lock 3 s. На каждый bag максимум 7 extra scenarios. Score/masks/recovery formulas те же; suite считается отдельно. Traces: первый подходящий переход каждого режима ([-.5,+2] s), original/extra fault onset/end ([-.5,+1] s), disturbance перед отказом и recovery. Это описательная диагностика, не post-hoc fitting.

## Наука
Zhang et al., Sensors 22(5),1787 (2022), DOI 10.3390/s22051787. Consensus поиск и abstract record; доступный текст издателя, особенно Remark 4: wheel-speed предпосылка неверна при slip, motor-speed/torque схема не наш интерфейс, CAN delays 1–20 ms не доказательство нашего L 50–200 ms. Scite вызван, но вернул monthly quota limit; citation contexts недоступны, ничего не покупать. Wolfram проверяет H(s)=K exp(-Ls)/(1+tau*s), step/frequency, units/limits/discrete pole и phase sensitivities. Устойчивость actuator при идеальных условиях не доказательство устойчивости полного nonlinear observer. L/tau при низких частотах смешаны; sensor lag/slip не идентифицированы отдельно.
