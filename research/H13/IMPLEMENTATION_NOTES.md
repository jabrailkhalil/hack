# H13: фиксация реализации до измерений

База: main e3b0c9c039d2953fbfcda51231263d38ef9f1024 (v8). Ни один файл src/, прежний evaluator, profile, freeze или тест не меняется. Новый Observer строится только в изолированных Python modules из исходного core с двумя явными hooks; исходный main исполняется отдельным классом.

Константы точно соответствуют H13_NEUTRAL_COMMON_ACCEL_PLAN.md. Никакого перебора. Новая пара требует двух ранее не использованных stamps; held samples допускаются при чередующихся callbacks, но не прибавляют подтверждений. Нарушение условий сбрасывает последовательность свидетельств. Карантин не меняет single-wheel correction, когда принят ровно один канал, даже если это уменьшает эффективность на асинхронных потоках. Недостаток будет измерен, не исправлен постфактум под результат.

Дополнительные anchors: первая точка с >2 м/с и разностью wheel speeds <0.15, после max(25 с,10% длины), при нейтральной команде на прошедшем 1-секундном окне. Будущая команда не используется для выбора; если она изменится в fault-окне, сценарий не выбрасывается. Два ramp-сценария строго из плана. Реальный evaluator и его original/H11 fault windows остаются неизменными. Новые FUSED/REACQUIRING counts измеряются именно внутри инъекции отдельным наблюдающим wrapper, метки отказа не передаются алгоритму.

12 локальных mechanism/invariant tests прошли до validation. Это не подтверждение выигрыша. После публикации FREEZE.json выполнить один фиксированный validation; повтор разрешён только для проверки воспроизводимости, без изменения параметров.

Новый независимый final test и train GNSS не читаются. Чистый CI проекта относится к неизменному активному v8; приёмка H13 отдельно требует всех accuracy gates и installed-candidate ROS/resource tests. До этого promotion запрещён.
