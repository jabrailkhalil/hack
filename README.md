# Резервная одометрия трамвая — пакет сдачи v4

ROS 2 Humble: нелинейная продольная модель, раздельная проверка тележек, адаптивная поправка, скорость и относительная дистанция. Runtime получает **только три vehicle-топика**, без GNSS, IMU, LLM, numpy или SciPy. Коэффициенты обучены на train в v3; в v4 до final test исправлены асинхронная инициализация/повторный захват, точность временных меток и задержка публикации.

## Быстрый запуск

В подготовленной Ubuntu 22.04 / ROS 2 Humble, из корня исходников или распакованного ZIP:

```bash
bash submission/build.sh
bash submission/run.sh
```

Во втором терминале:

```bash
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 bag play /absolute/path/to/bag --topics \
  /vehicle/driver_position_cmd \
  /vehicle/front_bogie_velocity \
  /vehicle/rear_bogie_velocity
```

`build.sh` не скачивает зависимости/данные. `run.sh` обязательно загружает финальный `config/default.yaml`: 20 Гц, `alignment_delay_s=0`, обученные коэффициенты. Голый `ros2 run` без params-file использует старые Config defaults и не равен сдаваемой конфигурации.

Для полного dropout при продолжающемся `/clock`: `bash submission/run.sh --clock` и `ros2 bag play ... --clock 100`. В обычном `input_stamp` режиме полное отсутствие всех входов останавливает источник времени. Независимые bags требуют перезапуска ноды; backward `/clock` seek начинает новый относительный сегмент.

## Существенный вопрос по положению

**Базовый выход `(s,0,0)` в `odom_path_1d` — относительная дистанция, не восстановленная GNSS/ENU xyz-траектория.** PDF допускает относительную одометрию при отсутствии абсолютной привязки, но README архива требует xyz. Карта, origin и маршрут стрелок не предоставлены/не подтверждены; из трёх продольных каналов произвольные повороты не определяются. Готовый known-route загрузчик остаётся опциональным и не извлекает карту из test GNSS.

Интеграл GNSS-скорости применяется только как явно обозначенная скалярная проверка расстояния. Из-за gaps эталона полный терминальный scalar drift не подтверждён для test; интервальные метрики не выдаются за полный дрейф или 3D-точность. Согласование координат остаётся внешним вопросом перед оценкой по xyz-контракту.

Масштаб входов `1/3.6` также остаётся явным эмпирическим допущением: README пишет м/с, фактическое отношение wheel/GNSS в исследованных записях близко к 3.6. [Вопросы организатору](docs/ORGANIZER_QUESTIONS.md) не заменяют его ответа.

## Проверки и воспроизводимость

44 dependency-free unit tests, 20 исследовательских проверок изоляции/причинности/freeze, настоящий установленный ROS launch, сценарии асинхронных колёс, dropout, NaN, pause и seek. Все подробности финальной сборки и измерений находятся в `submission/RESULTS.md` и `reports/final/`.

Timing-проверка измеряет не только callback, но и publisher→оба независимых result subscribers. Старый 60-мс alignment pilot превысил nominal задержку (p95 около158 мс); сохранён отрицательный результат и повторные измерения после исправления. Полный development-bag проигрывается при 1x в контейнере **2 CPU / 500000000 байт / без сети**. Результаты одного прогона не являются hard real-time/неограниченной гарантией отсутствия утечек.

Исследовательские зависимости нужны только для offline-evaluator в отдельном Python 3.13; не ставить их в системный Python 3.10 ROS. Исторические отчёты v1–v3 сохранены в docs/ и reports/research_v3/, но актуальная инструкция для сдачи — submission/.

Репозиторий остаётся приватным. Доступ жюри, изменение ACL и отправка формы платформы автоматически не выполнялись. Standalone ZIP можно передать отдельно разрешённым организаторами способом. Решение не является сертифицированным компонентом безопасности.
