## Единственный штатный запуск

В подготовленной Ubuntu 22.04 / ROS 2 Humble:

```bash
bash submission/build.sh
bash submission/run.sh
```

Сборка идёт в отдельный `install_main`, не использует старый `install/`. Эквивалент после сборки:

```bash
source /opt/ros/humble/setup.bash
source install_main/setup.bash
ros2 launch reserve_odometry odometry.launch.py
```

**Пакет устанавливает только:** `guarded_odometry_node`, `odometry.launch.py`, `champion_v8.yaml`. Сохранившиеся в source старые профили/launch нужны для исторических тестов; они не устанавливаются и не являются вариантами штатного запуска. Не запускайте внутренний executable без YAML: используйте launch выше. Для экспериментов создавайте отдельную ветку, не меняйте основной профиль без сравнения.

## Что проверено и что ещё ограничивает результат

Выполнены два полных локальных сравнения девяти оценивателей: все 19 per-bag JSON и prediction hashes совпали точно. На упаковке прошли 161 test invocation, 43 research-integrity tests и проверка wheel: один executable/launch/YAML. Исходники runtime и профиль совпадают с уже проверенным v8.

**Свежие ROS/Actions-тесты новой упаковки не объявлены пройденными:** новые задания GitHub завершаются до выполнения steps, логи отсутствуют. Рецепт проверки сохранён в CI и build.sh. Это изменение упаковки и однозначности запуска, не новая модель с неподтверждёнными коэффициентами.

Плавная общая ошибка обеих тележек остаётся слабостью: slow-ramp event RMSE v8 3.07148 м/с, восстановление в среднем 4.41 с; у некоторых более простых вариантов восстановление быстрее. Нельзя выдавать победу в основных метриках за защиту от любых отказов.

Положение `(s,0,0)` — относительная дистанция, **не восстановленная GNSS/ENU xyz-траектория**. Реальная карта/origin/маршрут не подтверждены. Масштаб входов `1/3.6` остаётся эмпирическим допущением до ответа организаторов. GNSS/IMU/LLM в runtime нет.
