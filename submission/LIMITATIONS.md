# Допущения, ограничения и дальнейшее развитие

## Существенные ограничения при сдаче

**Представление положения.** Базовый выход `(s,0,0)` — относительная одометрия вдоль пути. PDF на странице 5 допускает её при отсутствии абсолютной привязки; README архива требует xyz, согласованные с GNSS. Подтверждённой карты/pathgraph, origin и маршрута прохождения стрелок нет. Поэтому соответствие именно xyz-проверке не подтверждено. Из трёх продольных каналов нельзя однозначно восстановить произвольную геометрию пути. Интегральная ошибка скорости и скалярная дистанция в отчёте **не подменяют** 3D-ошибку.

**Единицы.** Входной scale 1/3.6 основан на наблюдении отношения wheel/GNSS около 3.6 на исследованных записях; README говорит м/с. Официального ответа об единицах скрытого теста пока нет. Коэффициент задан явно и не подстраивается по будущему GNSS.

**Истина и обучение.** Модель обучена на согласованной колёсной псевдоразметке без train GNSS. Общая ошибка двух тележек может попасть в target. GNSS-эталон неоднороден; отсутствующий reference отмечается null, оба приёмника показаны отдельно. Публикуется также coverage: ошибка по доступным парам не равна качеству всей записи без пропусков.

**Идентифицируемость.** Коэффициенты эффективные, а не паспортная масса/радиус/момент. Не оцениваются независимо истинные уклон, масса и сцепление. Полный EKF, физическая модель всех двигателей, карта, стрелки и GNSS-инициализатор не заявляются.

**Сбои.** Recovery эвристический. Правдоподобная одинаковая ошибка обоих каналов может быть неотличима от ошибки модели. Для нулевых заблокированных колёс действует защита от ложной остановки, но длительный юз без внешнего источника не имеет гарантии точности.

**Время.** `input_stamp` останавливает source clock при исчезновении всех входов; для полного dropout нужен `ros_clock`. Независимые bags требуют перезапуска/явного reset. При seek начинается новый сегмент. Известные тесты проверяют ограниченный набор пауз, пропусков, NaN и сдвигов времени, не любой сбой источника часов.

**Производительность.** Фактические результаты относятся к указанной машине GitHub Actions, подготовленному Humble-контейнеру и сохранённым сценариям. Средняя частота не доказывает дедлайн каждого сообщения. В timing-метриках перечислены непривязанные входы. Полный 24-минутный прогон не доказывает отсутствие утечек при неограниченном времени работы. Python/ROS нода не сертифицирована для управления безопасностью трамвая.

**Права и доступ.** Репозиторий приватный; GitHub-ссылка не означает доступ жюри. До отправки формы владелец должен согласовать доступ или передать standalone ZIP разрешённым способом. Приватность и ACL автоматически не менялись. Отправка формы платформы не выполнялась.

## План развития

После ответа организаторов — единая метрическая система, разрешённая карта, корректная bounded GNSS-инициализация только в начальном окне, real xyz/along-cross-track оценка. Далее — cross-vehicle-only проверка переноса, дополнительные независимо размеченные проскальзывания, калибровка covariance и отдельная оценка доверия к модели. Для промышленной эксплуатации — длительные аппаратные испытания, модель часов/пакетных потерь, watchdog, политика безопасной деградации и независимая верификация требований.

Финальный test после фиксации модели используется только для отчёта. Улучшение по его ошибкам будет новым циклом разработки и потребует другого независимого тестового набора.
