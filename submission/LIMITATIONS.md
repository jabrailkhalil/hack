# Ограничения и план развития

## Ограничения текущей версии

1. **Положение вдоль пути.** Без заданной карты публикуется `(s,0,0)` от начала прогона. PDF допускает относительную одометрию; README набора описывает XYZ-проверку. Соответствие пространственной проверке требует согласованных карты, системы координат и начальной привязки.
2. **Единицы входов.** Масштаб колёс `1/3.6` получен эмпирически. Единицы скрытых данных необходимо сверить; параметры преобразования заданы явно.
3. **Общая ошибка колёс.** Правдоподобный синхронный дрейф двух тележек может пройти проверки. В сохранённом сценарии плавного общего дрейфа RMSE скорости составляет 3.071476 м/с, среднее восстановление — 4.4075 с.
4. **Переносимость модели.** Коэффициенты получены на предоставленных записях; независимая оценка массы, уклона и сцепления не выполняется. Работа на других вагонах и погодных условиях требует проверки.
5. **Время.** При исчезновении всех входов `input_stamp` не продвигает модель. Для прогноза в таком сценарии используется `ros_clock` с продолжающимся `/clock`.
6. **Доказательная база.** Основные показатели v8 получены на повторно использованном validation-наборе. Сборка и функциональные ROS-проверки прошли; опубликованы два 60-секундных замера текущего v8. Независимый финальный тест и длительный замер v8 ещё не выполнены. Исторические замеры v4 относятся к другой версии.
7. **Неопределённость.** Ковариации эвристические; гарантии точности на длительном юзе и при неограниченной потере колёсных данных нет.

## План после хакатона

1. Уточнить единицы входов, пространственный контракт проверки и источник карты; реализовать начальную привязку по разрешённому окну GNSS.
2. Проверить проекцию `xyz=r(s)` на реальном маршруте, включая стрелки; измерять продольную и поперечную ошибки отдельно.
3. Собрать независимый набор записей других вагонов с размеченными случаями проскальзывания, юза и пропусков сообщений.
4. Улучшить обнаружение медленного общего дрейфа и восстановление после него; откалибровать оценку неопределённости.
5. Провести длительные ROS 2 испытания на целевом оборудовании с ограничением CPU и памяти, измерением задержки каждого выхода и проверкой часов.
6. Перед применением в управлении движением выполнить промышленную верификацию, добавить контроль работоспособности и согласованную политику деградации.

Источники показателей: [результаты v8](VALIDATION_V8.md), [таблицы сравнения](../reports/adjudication/REPORT.md).
