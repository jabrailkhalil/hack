# Демонстрация: 3–5 минут

**До показа:** подготовить ROS-среду, датасет по checksum, собрать через `bash submission/build.sh`. Открыть JUDGE_GUIDE, RESULTS и terminal. Не устанавливать зависимости на сцене. Использовать development bag 30618_0652866c, не выбирать удачный final-test участок по результатам.

**0:00–0:40.** Задача: резервно оценивать скорость/дистанцию по трём внутренним каналам. Показать `ros2 node info /reserve_odometry`: GNSS/IMU нет. Сразу обозначить относительный режим положения и отсутствие карты.

**0:40–1:40.** `bash submission/run.sh`, затем `ros2 bag play ... --topics` по JUDGE_GUIDE. Показать скорость, растущую/останавливающуюся s, корректные stamps/frames и 20 Гц. Объяснить нелинейную модель привода и раздельное доверие тележкам.

**1:40–2:40.** Остановить bag и ноду; запустить `python3 tests/ros_fault_smoke.py` в подготовленном workspace. Этот сценарий запускает установленную ноду, разносит wheel-сообщения по времени, исключает колёса на 5 с и все входы на 3 с при продолжающемся /clock, вводит некорректные данные, затем паузу и обратный seek. PASS подтверждает заложенные инварианты. Это ускоренное сценарное испытание, не измерение реальной задержки.

**2:40–3:40.** Открыть результаты: финальный test отдельно от validation; обе GNSS-системы, missing reference, fault windows. Показать полный ROS runtime report с 1x replay, задержкой publisher→оба независимых подписчика, памятью и непривязанными входами. Не называть интеграл скорости 3D-ошибкой.

**3:40–4:30.** Показать FREEZE.json, история checkpoint-коммитов и автономный ZIP. Пояснить: коэффициенты обучены на train, исправления runtime проверены до final test, после него параметры не подбирались. Завершить конкретными ограничениями из LIMITATIONS и планом карты/инициализации.
