# Tram Odometry Lab — демонстрация решения

Карта поездки, графики скорости и пути, сравнение моделей и сценарии отказов — в одном интерфейсе. Выберите запись, сравните оценки с GNSS и разберите моменты, когда колёсные измерения становятся ненадёжными.

![Tram Odometry Lab: анализ поездки и сравнение моделей](../reports/submission_20260927/web-demo.png)

На скриншоте v8 выбран первым: верхние показатели относятся к нему. Это одна development-запись `30618_0652866c`; общие результаты validation приведены в отдельном отчёте.

**Сценарий на три минуты:** выбрать поездку → сравнить v8 с базовыми оценками → добавить пропуск датчика → посмотреть восстановление и сохранить результаты.

Интерактивный стенд запускается локально по инструкции ниже. Скриншот доступен сразу, без установки.

В проект включена проверенная копия **Tram Odometry Lab** из [godknows1337/tram-odometry](https://github.com/godknows1337/tram-odometry), ревизия `e4be65ae8fc5a51c8a43f656dfe804877d985e55`. Исходники находятся в `web/tram-odometry`; для сборки достаточно этого публичного репозитория. Сведения об исходной версии сохранены в [UPSTREAM.json](../web/tram-odometry/UPSTREAM.json).

## Что показывает интерфейс

- список поездок и наличие GNSS;
- запуск v8 и базовых оценок front/rear/mean на выбранных записях;
- графики скорости, пути, ошибок и диагностики с общей шкалой времени;
- сценарии пропусков, задержек и искажений колёсных данных;
- очередь экспериментов, результаты и выгрузку CSV;
- карту для просмотра записи и отдельную исследовательскую страницу «Маршрут и GNSS».

Для демонстрации сдаваемой модели выбрать **hack_v8** без переопределений параметров. `hack_v8_traction_only` и остальные варианты служат для исследований. Проверка `python tools/check_web_integration.py` подтверждает совпадение ядра, временного буфера и параметров v8 с основным репозиторием.

## Роль в решении

Обязательные топики `/result/velocity` и `/result/position` публикует пакет `reserve_odometry`. Веб-интерфейс запускает офлайн-эксперименты с записями; подключение к живым ROS-топикам в этой интеграции не реализовано. UI не требуется для сборки ROS-пакетов и исключён из поиска colcon файлом `web/COLCON_IGNORE`.

Веб-адаптер использует ядро v8, но запускает его на временной шкале получения событий стенда. Его метрики могут отличаться от результатов штатной ROS-ноды. Время офлайн-расчёта не является ROS-задержкой.

Обычная карта показывает проекцию оценённого пути на GNSS-маршрут записи. Она помогает анализировать движение, но не доказывает восстановление абсолютной траектории без GNSS. Вкладка [«Маршрут и GNSS»](http://localhost:8080/#research) в верхней панели требует внешней карты и имеет отдельную методику; она не включена в сдаваемую ROS-ноду.

## Получение исходников и данных

Из корня `hack`:

```bash
python tools/check_web_integration.py
python tools/get_dataset.py
```

Загрузка набора нужна один раз. Скрипт проверяет SHA256 и сохраняет исходный архив организатора. Интерфейс использует `dataset/organizer/data.zip` и определения сообщений из `dataset/organizer/tram_vehicle_msgs/msg`.

## Запуск через Docker

Требуется Docker с Linux-контейнерами. Из корня репозитория:

```bash
docker compose -f web/compose.yaml up -d --build
```

Открыть [http://localhost:8080](http://localhost:8080). Остановка: `docker compose -f web/compose.yaml stop`. Данные подключаются только для чтения, результаты сохраняются в `web/runs`, модели — в `web/models`. Первая сборка загружает зависимости; подложка карты требует интернета.

## Запуск в Windows без Docker

Требуются Python 3.12 и Node.js 22 с npm. В PowerShell, из корня репозитория:

```powershell
py -3.12 -m venv .venv-web
.\.venv-web\Scripts\python.exe -m pip install -r web/tram-odometry/odometry_lab/requirements.txt -r web/tram-odometry/odometry_lab/requirements-web.txt
.\.venv-web\Scripts\python.exe -m pip install --no-build-isolation --no-deps -e web/tram-odometry/odometry_lab
npm --prefix web/tram-odometry/odometry_lab/frontend ci
npm --prefix web/tram-odometry/odometry_lab/frontend run build
.\.venv-web\Scripts\python.exe tools/run_web.py
```

После запуска открыть [http://localhost:8080](http://localhost:8080). Остановка — Ctrl+C. Другой порт: `--port 8081`; другой каталог данных: `--dataset C:\path\to\organizer`.

## Короткая демонстрация для жюри

1. Открыть «Данные» и выбрать development-запись `30618_0652866c`.
2. Создать эксперимент с `hack_v8`, `front` и `mean`, без обучения и изменения коэффициентов.
3. Открыть результат и показать графики скорости, ошибки и пути; сверить покрытие GNSS.
4. Добавить отдельный эксперимент с пропуском колёсных измерений, сохранив доступную команду управления.
5. Показать реакцию модели и восстановление. Выгрузить метрики и CSV через интерфейс.
6. Для проверки ROS-публикации выполнить отдельный запуск из [инструкции жюри](JUDGE_GUIDE.md).

Подробная документация исходного UI: [WEB.md](../web/tram-odometry/odometry_lab/WEB.md). Пакет дополнений `tram_web_integration_20260926`, лежащий рядом с локальным проектом, повторно применять не требуется: выбранная ветка уже содержит эти дополнения и исправления после проверки.
