# Маршрут и GNSS в веб-лаборатории

Основа: `codex/odometry-web-lab@b134a8898f255b72af9dc085a97de8c6eb010823`.
Это отдельный исследовательский интерфейс. Основной v8, старые страницы и scorer не заменены.
**Traction-only не прошёл новый native development:** на 30618 fault-event RMSE +9.94%.
Подробные результаты, ограничения проверки и причины решения: [RESEARCH_REVIEW.md](RESEARCH_REVIEW.md).

## Запуск

В полном checkout новой ветки, с прежним dataset рядом с репозиторием:

```bash
cd odometry_lab
docker compose up -d --build
```

Откройте локальный UI на `http://127.0.0.1:8080/#research`, вкладку «Маршрут и GNSS».
Это существующий рецепт Docker; его выполнение здесь не заявляется. Старый App
остаётся смонтированным при переключении, выбор предыдущих запусков не стирается.

## Сравнение скорости

Выберите 30618, 30639 или оба трамвая, затем development-поездки. Кнопка добавляет
v8 и `hack_v8_traction_only` в прежнюю очередь worker. Сценарии: clean либо выпадение
обеих колёсных скоростей с указанными границами; controller остаётся доступен.
Остальные сценарии доступны через прежнюю форму эксперимента.

После завершения обновите список и выберите два сохранённых запуска. Проверяются
одинаковые часы, reference, маски, доступность прогнозов, настройки отказов и SHA
записей. Нельзя скрыть разные области пересечением списков. Group-macro и pooled
показываются раздельно; отсутствие reference не даёт нулевую ошибку.

Новый API разрешает только исходные 17 development ID проекта hack, 15 уникальных
DB; повторные идентичные данные не получают второй вес. Это не хронологический
validation старой веб-лаборатории и не independent test. Native-эксперимент в отчёте
сохраняет исходный frozen состав 17 ID и имеет другие часы: числа не взаимозаменяемы.

Профиль traction-only использует прежний HackEstimator/GuardedReadoutObserver v8:
только torque=3149.748421403977 и power=429127.7144908343; brake=45568.80940352644.
Собственная конфигурация включена с начала записи, GNSS в speed estimator не поступает.
Нет автоматического обучения, переключения default или выбора победителя.

## Отдельная привязка положения

Загрузите внешний направленный маршрут, выберите saved run/bag, один receiver,
интервал GNSS, стартовое окно и ограничение поправки. Сравниваются initial-only и
sparse. Исходная скорость и raw_distance неизменны: меняется только offset в
`route_s = raw_distance + offset`. Полный результат записывается новым JSON;
старые CSV/метрики не перезаписываются. Для отображения массив прореживается.

Пример ниже задаёт только формат, **не карту реального маршрута**:

```json
{
  "schema": "tram-route-enu-v1", "frame": "ENU",
  "source": "Имя внешнего Pathgraph, версия, SHA256, способ преобразования",
  "origin_wgs84": [55.0, 37.0, 100.0],
  "reference_point": "base_link", "height_reference": "unknown",
  "paths": [{"id": "route-1", "direction": "forward", "closed": false,
             "points": [[0.0, 0.0, 0.0], [100.0, 0.0, 0.0]]}]
}
```

Origin: широта/долгота в градусах и эллипсоидальная высота в метрах; points: ENU.
Параметры примера нельзя брать за реальный origin. До 16 путей/20000 сегментов,
без соединения по близости. При неоднозначности алгоритм отказывается от привязки.
После выбора путь фиксирован. Open path при исчерпании возвращает OUTSIDE_ROUTE;
явный `closed:true` допускает круг, только если последняя точка равна первой.

**Официальный Pathgraph не получен.** Нужны его bytes, CRS, origin, точка карты и
высотный datum. Текущая GNSS-линия старой страницы «Анализ» использует всю поездку
и не передаётся этому алгоритму. Неизвестный MGRS не переименовывается в ENU.

## GNSS-правила и ограничения

Стартовое окно по умолчанию 3 с от начала bag; после первой привязки в этом окне
коррекций нет. Затем первое сообщение receiver в каждом 30-секундном слоте выбирается
до quality/model gates. Плохой fix не заменяется удобным из того же слота.
Запоздавшее измерение сопоставляется с уже доступной историей на source timestamp.
Будущие/старые/повторные метки, NaN status, смена frame, чрезмерный остаток и
неоднозначная проекция отклоняются. История ограничена 128 отсчётами.

После сброса, потери raw s или publication-gap >0.2 с старая привязка недоступна;
после уже выполненной инициализации требуется явный новый replay, окно не открывается
заново. Gain=.35, max age=.5 с, max step=5 м и другие пороги — инженерные настройки,
не параметры, измеренные на hidden test, и не гарантии организаторов.

По пользовательской сводке: master=(-9.873,0,3), rover=(2.563,0,3) м относительно
base_link. Плечи поворачиваются по касательной/pitch сегмента, roll=0 — приближение.
7.55 м между тележками не принято за расстояние между антеннами. Сводка отмечена
USER_SUPPLIED_ORGANIZER_SUMMARY; оригинальные сообщения отдельно не проверены.
Scorer XY/XYZ, base_link/antenna и Z datum не подтверждены: official_xyz_score=null.
Коррекции и их residual не являются независимой проверкой точности.

## Проверки

```bash
PYTHONPATH=src python -m pytest -q tests/test_research_integration.py tests/test_research_review.py
python scripts/validate_research_ui.py --chromium /usr/bin/chromium --output /tmp/research-ui-fresh
```

Для browser script нужны pytest, Playwright и Chromium. Он исполняет реальный HTML/JS,
но использует синтетические ASGI fixtures, не сеть/реальный worker. Выполнено 81 test
и 11 browser checks; точная среда и hashes — RESEARCH_REVIEW_VERIFICATION.json.
Полный React/Vite build, весь старый test suite, worker/Docker/ROS остаются непроверенными.
В полном окружении дополнительно выполните `python -m pytest -q`, затем
`cd frontend && npm ci && npm run build`.

API: GET `/api/v1/research/{contract,page,page.js}`, POST `enqueue`, `compare`,
`localize`. Запрос до 2.5 MB, CSV до 128 MiB/180000 ticks, одна локализация на процесс.
Это локальный исследовательский стенд, не многопользовательский production service.
